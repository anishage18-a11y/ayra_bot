Some features store information in local SQLite databases. AI requests may be sent to Groq, search requests may be sent to Google/SerpAPI, and other feature-specific requests may be sent to third-party APIs.

This Privacy Policy explains how the operator of Ayra (“we”, “us”, “our”) processes information when you interact with Ayra on Discord.

Ayra is an independent third-party Discord application and is not operated, sponsored, endorsed, or affiliated with Discord Inc. Discord separately processes information under its own privacy policy.

3. How Message Content Is Used

Ayra may receive message content because several features operate on messages, including AI chatbot responses, automoderation, anti-spam and anti-link protections, autoresponders, counting, AFK notifications, message tracking, snipe/edit-snipe, and other utilities.

Not every message is permanently stored. Some features process content transiently and only store configuration, counters, or limited history. Where content is stored, the relevant feature-specific retention described below applies.

4. AI Processing

Ayra’s AI features use Groq’s API. When you use AI chat, AI questions, translation, or another Groq-powered feature, the content necessary to generate the response may be transmitted to Groq. For chatbot conversations this can include your current message, recent conversation context, and applicable personality instructions.

Groq currently states that inference customer data is not retained by default, except in limited circumstances such as system reliability or abuse monitoring, and that such reliability/abuse logs may be retained for up to 30 days. Groq also states that usage metadata is retained. These third-party practices are controlled by Groq and may change.

See Groq's current data documentation and Groq's Privacy Policy.

5. Feature-Specific Storage and Retention

AI conversation memory

The AI chatbot stores recent user/assistant conversation messages in conversation_memory. The current implementation automatically removes entries older than approximately 24 hours when the cleanup process runs for the relevant conversation.

AI chatbot history and personality

A separate chatbot_history table stores the user’s message, Ayra’s response, user ID, guild ID and timestamp. The current implementation does not automatically expire this table. It remains until the user clears their Ayra data, the server data is removed/reset, or a valid deletion request is processed.

Saved personal AI personality preferences are stored in user_personalities until cleared or deleted.

AI data deletion command

The current ai database-clear command deletes the user’s conversation memory, chatbot history and personal personality for the current server. You can also request deletion by contacting discordlabbd@gmail.com.

Roleplay and temporary AI context

Roleplay history is maintained in application memory while the roleplay session is active. The current roleplay flow does not intentionally write that roleplay history to the AI database, although the content may still be transmitted to the AI provider when needed to generate responses.

Message tracking

If message tracking is enabled, Ayra stores per-user message counts and daily message counts by guild. It does not need to store the full message text for this feature. Invite tracking can store inviter ID, invited-user ID, invite code, join time and whether the invited member later left.

Leveling

When leveling is enabled, Ayra stores guild/user IDs and XP/level information and may use server-configured level roles and multipliers.

AFK

The AFK feature can store your user ID, AFK status, reason, timestamp, mention count, server association and notification preference. When another user mentions an AFK user, the bot may process the mentioning message and may send the message content to the AFK notification destination configured by the feature.

Tickets and transcripts

Ticket records can contain creator, claimer, closer, reason, category, urgency/priority, timestamps, ratings and feedback. When a transcript is requested or a ticket is closed, Ayra can read the ticket channel history and generate an HTML transcript containing message text, display names, timestamps and attachments. The generated transcript is sent through Discord; the current code does not intentionally save the generated HTML transcript in a local database.

Server backups

When an administrator creates a backup, Ayra stores the server name, creator ID and serialized server configuration, including roles, channels, categories, topics, permission overwrites and emoji URLs. Permission overwrites can contain role or member identifiers. Backups are user-created and may be deleted with the available backup deletion feature.

Todos, counting and other user content

Depending on the features used, Ayra can store todo tasks, counting expressions/results, autoresponder messages, sticky messages, custom-role configuration, giveaway/ticket configuration, warnings, blacklist/block records and other server-specific settings.

Snipe and edit-snipe

The snipe feature keeps a limited in-memory cache of recently deleted or edited messages, including author information, message content and attachment URLs. The current implementation limits the cache to approximately 10 entries per channel and does not intentionally persist this cache to the SQLite databases.

Command and interaction logging

The current bot code sends command-completion metadata to an operator-controlled Discord webhook when configured. This can include command name, guild name/ID, channel name/ID, user name/ID, avatar URL and timestamp. The webhook destination determines its own retention and access practices. The bot operator should restrict access to this webhook.

6. Third-Party Services

Depending on which commands are used and which API keys are configured, Ayra may send feature-related information to third-party services. Examples include:

  • Groq: AI chat, translation and related AI requests.
  • Google Custom Search / SerpAPI: search and image-search queries.
  • Giphy / Tenor and other media providers: GIF/media searches.
  • OpenWeather: weather queries such as the city requested.
  • Cryptocurrency providers: market, price, news or blockchain queries, which may include a cryptocurrency symbol, asset name, transaction hash or blockchain address entered for the feature.
  • Other public APIs: certain games, fun, quote, image, speech, anime/media and utility commands may contact their respective service providers.

Third-party providers have their own privacy policies and terms. We do not control their independent processing or retention practices.

7. Data Sharing

We do not sell Ayra user data as a business model. Information may be shared or made available to:

  • Discord, as necessary to operate a Discord application and send/receive Discord data;
  • third-party API providers when a feature requires their service;
  • the server administrators and moderators who configure or receive Ayra logs, tickets, transcripts, moderation results or tracking information;
  • the operator’s infrastructure and service providers used to host and maintain Ayra;
  • authorities or other parties where disclosure is required by law or reasonably necessary to protect users, the Service, or legal rights.

8. Data Retention

Retention depends on the feature. Some information is automatically short-lived, while configuration and history databases may remain until reset, deletion, or a valid request. Because Ayra is installed into independently managed Discord servers, some information may also remain in Discord or in a server administrator’s own logs, backups, transcripts, or screenshots after Ayra data is deleted.

9. Your Choices and Deletion Requests

You may stop using Ayra or ask a server administrator to remove Ayra from a server. For data stored in Ayra-controlled databases, you may request access or deletion by emailing discordlabbd@gmail.com.

When appropriate, we may ask for your Discord User ID or other information needed to verify the request. We will delete applicable data from systems under our control within a reasonable period, subject to legitimate legal, security, backup, or operational exceptions.

Deletion from Ayra does not automatically delete information already stored by Discord, third-party API providers, server administrators, or other independent services.

10. Security

We use reasonable measures intended to protect Ayra-controlled data. No online service, Discord bot, database, webhook, or network transmission can be guaranteed to be completely secure.

Do not send passwords, Discord tokens, API keys, private keys, payment-card details, or other secrets to Ayra.

11. International Processing

Ayra and its third-party providers may process information outside your country. For example, Groq currently states that customer data retained by its services is stored in Google Cloud Platform infrastructure in the United States. International processing may therefore involve different privacy laws and safeguards.

12. Children and Age Requirements

Ayra is not intended to bypass Discord’s age requirements. We do not knowingly request personal information from children in violation of applicable law. If you believe information has been collected in circumstances where it should not have been, contact us at discordlabbd@gmail.com.
